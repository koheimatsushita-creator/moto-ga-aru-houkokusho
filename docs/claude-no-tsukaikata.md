# Claudeの使い方の記録

このリポジトリは、Claude Code を開発の中心に据えて作った。依頼者（オーナー）はプログラマーではなく、確認と判断をした。ここには実際にやったことだけを書く。予定していて作らなかった物も書く。

## 1. 作る係と確かめる係を、別の会話に分けた
- **作る係**：このリポジトリで動く Claude Code の会話。仕様（docs/requirements.md・docs/design.md）を読み、コード・架空データ・試験・文書を書き、コミットまでを行った。2026-11-03 からは、オーナーの「本体」の Claude から1回ずつ呼び出される形で動いた（GitHubへの送信はオーナーが行う）
- **確かめる係（本体）**：作る係の報告を受け取り、オーナーに判断を仰ぎ、ブラウザで見本5組を最後まで通す確認や、鍵の置き場の不具合（二重の貼り付け）の修正を行った
- 確認が要る操作が自動で断られた時は、作る係は回り込まずに止めて「何をしたいか・なぜ必要か」を報告した。サンドボックスの外での実行や、ブラウザの取り込みが断られた時も同じ
- 手元の起動はサンドボックスの中で行った（Turbopack がファイル監視を開始できなかったため、webpack に切り替えた）

## 2. アプリの中で、モデルと機能を目的に合わせて使った
- **検査役**：Claude API の claude-opus-5-5（effort medium、max_tokens 4,000）。下書きを書いたやり取りは渡さず、訪問記録と番号つきの文だけを渡す
- **構造化出力**：判定・根拠の記録番号・引用・理由を、決めた形（zod の型）で受け取る
- **文の分割はAIに任せない**：普通のプログラムで句点と改行で分ける（文を飛ばされないため）
- **サーバー側の確かめ直し**：AIの答えを、引用が記録に一字一句あるか、文と重なるか、などで機械的に確かめ直す。11/4 までの5組の測定では判定を直したことは無かった（0回）。11/5 の50組×3回では、AIが引用を空で返した13件を根拠なしに下げた（docs/kensho-kiroku.md）
- **下書きを書くAI（書き手役）は作らなかった**：設計では「あれば便利、最後に作る」の位置づけで、時間の都合で見送った
- SDK の書き方とモデル名・料金は、Claude Code の claude-api の手引きと公式の料金ページで確かめてから書いた

## 3. 判定の揺れを測った
- `npm run judge:fixtures`：見本5組を検査役に通し、正解との一致と、秒数・トークン数・費用を記録した
- `npm run eval`：同じ5組を4回ずつ通し、指示2版で計8回測った（当初の20組の予定を、正解付けの手間のため変更）
- 測定の結果を見て指示を2回足した（「反する」と「根拠なし」の境目、全部の記録を読む）。指示の調整と測定に同じ5組を使っており、別に取り分けた試験用の組は無い
- 正解は作る係の Claude が付けた。境目のルールを書いた後、そのルールに照らして2件を直した（2件ともAIの答えの側に動いた）。看護の専門職は確認していない
- 2026-11-05（オーナー承認）：「5組に合わせただけでは？」に答えるため、作る係の Claude が、指示を作る時に一度も見ていない架空の45組（fixtures-holdout/）を作った。先に種類を決めてから文を書き、境目の難しい文に印を付け、機械の点検（`npm run check:holdout`）を通して、**検査役に通す前に正解をコミットした**。そのあと既存5組と合わせて50組×3回を通した。検査役の指示とコードは変えていない。結果を見た後に、作り方の誤りとして正解を5文直した（5文ともAIの答えの側）。直す前の値も残した
- 詳しくは docs/kensho-kiroku.md

## 4. 公開の前に、別の目で3つ確かめさせた
- 本体が、進め方の点検役・セキュリティの点検役・Codex の3つに確認させた。セキュリティと Codex は「このままでは公開を止める」、進め方は「条件付きで進めてよい」だった
- 指摘を受けて直した物：本番で上限の仕組みが欠けた時に止める、AIを呼ぶ前に回数を確保する、入力の上限、よそのサイトからの送信を断る、紛れ込ませた指示への備え、個人情報の形の検査の強化、検証の数字の書き方（赤か赤でないかを主にし、幅で書く）など

## 5. 予告動画は別の会話に分けた
- 予告動画はアプリのリポジトリとは別の場所・別の会話で作る形にした。アプリのリポジトリには動画用の部品を入れていない
- 作る係の会話でも一度着手したが、画面を撮るヘッドレスのブラウザがサンドボックスの中で起動できず、止めて報告した

## 6. 公開版は見本だけにした
- 2026-11-04 オーナーが決めた：公開版では実行モード（誰でも文を貼ってAIに照合させる形）を止め、見本モードだけを動かす。実データが入る可能性のある物を認証なしで公開しないというルールに当たるため。AIでの照合は、手元で動かした様子を動画で見せる
- 1つのスイッチ（wrangler.jsonc の RUN_MODE）で開け閉めでき、閉じている時はAIを呼ばないことを試験（npm run check:limits）で確かめた

## 7. 予定していて作らなかった物
- .claude/skills（報告書様式・架空データ作成）、.claude/agents（判定の試験役）、.claude/settings.json のフック：作っていない。試験役の代わりに、正解と突き合わせる処理を `npm run judge:fixtures`・`npm run eval` のスクリプトとして書いた
- コミット前の鍵の形の検査だけは、githooks/pre-commit として足した（鍵の中身は表示しない）。電話番号の形はコミット前には見ていない（架空データの検査 `npm run check:fixtures` で見ている）
