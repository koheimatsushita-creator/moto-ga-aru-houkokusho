# 設計

## 処理の流れ
1. 文の分割は普通のプログラムで行う（Claudeに任せない。文を飛ばされないため）。句点と改行で切り、番号を付ける
2. 検査役（Claude Opus: claude-opus-5-5）に、訪問記録と番号つきの文だけを渡す。下書きを書いたやり取りは渡さない
3. 構造化出力で、文ごとに { sentenceId, verdict, evidenceIds[], evidenceQuote, reason } を受け取る（zodで検証）
4. 機械の検査（Claudeに判定させない）
   - 返ってきた文の数が入力と同じか。足りない文は「根拠なし（未判定）」にする
   - evidenceQuote が、指定された記録の本文に文字どおりあるか。無ければ「根拠なし（引用が記録に無い）」に下げる
   - reason に言い切りの語（安全、問題ありません、正しい等）が無いか
5. 書き手役（Claude Sonnet: claude-sonnet-5-5）は、実行モードで「記録から下書きを作る」を選んだ時だけ動く。あれば便利の位置づけで、最後に作る

モデル名と構造化出力の書き方は、実装の時に公式の文書で確かめる（claude-api のスキルか platform.claude.com）。

## データの型（fixtures と共通）
- VisitRecord: { id: "R01", date, staffRole, lines: string[] }
- Sentence: { id: "S01", text }
- Judgement: { sentenceId, verdict: "一致"|"言い換え"|"根拠なし"|"反する", evidenceIds, evidenceQuote, reason }
- Decision: { sentenceId, action: "戻す"|"削る"|"残す", reason? }
- 架空の組: fixtures/case-01.json など。{ records, draft, expected（正解の判定）, savedJudgements（実際に回した結果） }

## サーバー側
- POST /api/judge: 入力 4,000字まで。個人情報の形の検査をサーバーでも行う。max_tokens 4,000。1回の呼び出しは60秒以内に収める。切れたら失敗の文言を返す
- ANTHROPIC_API_KEY は Cloudflare の Secrets（ローカルは .dev.vars）
- 回数の上限（実行モードだけ。見本モードには掛けない）：全体で1日30回（Workers KV に日本時間の日付ごとの回数）＋同じ接続元から1分3回（Workers の Rate Limiting）。上限はサーバーで止める
  - 公開した物では、上限の仕組みが欠けていたらAIを呼ばずに503で止める。手元の npm run dev だけ素通り
  - 1日の回数は、AIを呼ぶ直前に1回分を確保して数える。AIに届いた後の失敗（打ち切り・途中切れ・形の不一致）も数える。数えないのは、AIに届く前に断った時（400・403・413・422・429・503）だけ
  - 全体の上限なので、1人が使い切った日は、ほかの人も実行モードを使えない（見本モードは使える）
- 数え漏らしの幅：KV は「読んでから書く」数え方なので、同時に来た分は数え漏らす。AIを呼ぶ前に確保することで、漏れる間口は「読んでから書くまで」の短い間に狭めた。ただし KV はほかの場所への反映に最大1分ほど掛かるため、別々の場所から同時に来た分は、1分の間に（接続元の数×3回）程度まで上限を超えうる。D1 や Durable Objects は足さない。最後の止めは、依頼者の Console の月30ドルの支出上限（1回あたり約0.03〜0.13ドル）
- 入力の上限（AIを呼ぶ前に止める）：本文32KB（JSONを読む前）、記録と下書きの合計4,000字、下書き4,000字、60文、記録40件、1記録30行、1行300字、記録番号の重複は不可。日付欄は日付の形だけ、職種欄は決めた一覧だけ。個人情報の形の検査は全部の欄に掛ける
- よそのサイトから訪問者のブラウザで叩かれないよう、Content-Type が application/json でない時、Origin・Sec-Fetch-Site が自分のサイトでない時は403
- 502の返事には失敗の中身（理由・トークン数）を入れない。中身はログだけ
- wrangler.jsonc の preview_urls は false（上限を通らない入口を作らない）

## 端末内の止め方
送信前に、氏名らしき語（「◯◯様」「◯◯さん」、利用者A〜E以外の姓名の形）、電話番号、郵便番号と住所の形、生年月日の形を検出して送らない。

## 試験
- npm run eval: fixtures の組を検査役に何回か通し（当初の20組を、5組×4回×指示2版に変更。理由：正解付けの手間）、正解と突き合わせて「言い換えを根拠なしと取り違えた数」「根拠なしを見逃した数」を出す。結果を docs/kensho-kiroku.md に残す（日付、モデル、入れ替えた指示、正解を付けたのは誰か）
- 見逃し（根拠なしを一致とした数）を最優先で減らす
- 通しの確認: 利用者の順に入口→照合→処理→出す→印刷。見本モードと実行モード
